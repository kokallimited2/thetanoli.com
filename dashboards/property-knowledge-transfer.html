🧮 SDLT Calculator Reference

Current Rates (England & NI, May 2026)
  • Up to £250k — 0%
  • £250k–£925k — 5%
  • £925k–£1.5M — 10%
  • Above £1.5M — 12%
  • FTB relief: 0% up to £425k, 5% on £425k-£625k, standard above £625k
  • Additional property: +5% surcharge on all bands
  • Non-UK resident: +2% surcharge
Verification Examples
  • FTB @ £400k → £0
  • Standard @ £500k → £12,500
  • Additional @ £300k → £17,500
  • Additional @ £500k → £37,500
  • Non-UK @ £300k → £8,500

Full JS logic + UI pattern + HowTo schema in references/sdlt-calculator-reference.md. ⚠️ Rates change with each UK Budget — verify at gov.uk/stamp-duty-land-tax before reusing.

🚀 Site Deployment Patterns

⚠️ Cloudflare Cache Pitfall
  • GH Pages deploy is instant, but Cloudflare edge serves old content for up to 2 hours
  • Always verify with cache-bust: curl -sI "https://domain.com/page?_cb=1"
  • Manual purge: Cloudflare Dashboard → Caching → Purge Everything
  • API purge: curl -X POST "https://api.cloudflare.com/client/v4/zones/{ZONE_ID}/purge_cache" -H "Authorization: Bearer {TOKEN}" -d '{"purge_everything":true}'
Standard Site Architecture
domain.com/
├── index.html              # Homepage — hero, tool cards, lead capture, FAQ schema
├── calculators/
│   ├── brrr.html           # BRRR calculator w/ HowTo schema
│   ├── rental-yield.html   # Rental yield calculator w/ HowTo schema
│   └── deal-analyser.html
├── guides/                 # Area guides, strategy articles
├── blog/
│   ├── index.html          # Blog listing (or root /blog.html)
│   └── post-*.html         # {slug}.html
├── assets/
│   ├── logo.svg | favicon.svg | og-image.svg
├── post.json               # Blog post index (append-only)
├── sitemap.xml
└── robots.txt
Schema Strategy
  • WebApplication — calculator pages (rich result as app)
  • Organization — all pages (brand authority)
  • HowTo — each calculator (step-by-step → triggers rich result)
  • FAQPage — listing/index pages (5+ Q&A)
  • BreadcrumbList — all pages
  • Article — blog posts (author: real name for E-E-A-T)
Blog Content Standards
  • Min 1200 words, practical authoritative tone — no fluff
  • Table of Contents at top, h2 sections with matching id anchors
  • FAQ section at end (5+ questions minimum)
  • Highlight box for key takeaways / CTAs
  • Internal links to calculators: /brrr-calculator, /#yield-calc
  • Author attribution: real name + Person schema (e.g. "Ateeq Yousif")
  • Blog cards: newest first, prepend to .blog-grid
  • Update: post.json, blog/index.html (prepend), sitemap.xml

🎯 Lead Generation Methods

1. Property Portal Filtering
  • Filter: reduced >10%, long-listed, chain-free, probate, auction
  • Watch for SSTC falling through → relisted
  • ⚠️ Rightmove/Zoopla use aggressive Cloudflare bot protection
  • Workaround: OCR from screenshots, cached pages (Google cache, Bing cache), API alternatives — see references/portal-extraction-workarounds.md
2. Probate Leads
  • Search "probate [area]" on portals
  • Check local probate registry listings
  • Cross-reference with Zoopla/Rightmove for matching addresses
  • Direct mail to probate executors
3. Expired Listings
  • Properties removed from market without selling
  • Check agent websites for SSTC that reverts to For Sale
  • Direct mail to owners of long-listed properties (180d+)
4. Auctions
  • Monitor: SDL Auctions, IAMSOLD, Auction House, Purple Bricks
  • Look for: no chain, below-guide prices, unusual property types
  • Forced sale timeline = motivated vendor

📝 Instructions & Advice for Nikka

🎯 Key Operating Principles
  1. You own property—fully. All three domains (pforprofits, pforproperty, dfordeals) are yours to operate, publish, and optimize. Wadda only does the dashboard upload at 7am.
  2. Use the Property Search Engine. Once deployed, it's your most powerful tool — scans 30+ deal types per postcode, scores BRRR/BTL/Flip, feeds your dashboard. Deploy it as soon as we get the API keys.
  3. Dashboard is your output hub. Update property-data.json with deals, area research, market intel, and leads. Push to the repo → Wadda picks it up at 7am.
  4. Blog weekly (Monday 8am). 1200+ words, practical UK property content. Use the pforprofits blog system reference. Update post.json, prepend to blog-grid, update sitemap.
  5. Portal scraping is broken. Rightmove/Zoopla blocks bots with Cloudflare. Use the extraction workarounds in the reference docs — OCR screenshots, cached pages, or manual entry.
  6. Cache-bust everything. After deploying to GH Pages behind Cloudflare, verify with ?_cb=1. The edge cache will show stale content for 2 hours otherwise.
  7. BRRR quick test: Purchase price ≤ 80% of post-refurb value. If not, it's a BTL hold, not a BRRR.
  8. SDLT rates change with budgets. Verify gov.uk/stamp-duty-land-tax before using in client-facing materials.
  9. PropIQ can be monetized. 4 models available — B2B SaaS (£9.99-99/mo), affiliate partnerships, white-label to agents, or freemium B2C. Pick one and run with it.
  10. Coordinate via WS hub. Send dashboard updates as WS broadcast (topic: "dashboard-data"). For urgent items, use topic "urgent" with needsReply flag.

  • Prop Search Engine deployed and feeding live deal data to dashboard
  • Weekly blog posts publishing on Monday 8am without fail
  • Dashboard updated daily with real deals, area analysis, and intel
  • At least one deal lead generated per week (from auctions, expired listings, probate)
